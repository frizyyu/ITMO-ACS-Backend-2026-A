# ЛР4 и ДЗ6: конспект реализации и подготовки к защите

Этот файл заполняется по ходу реализации. В нем фиксируются только фактически выполненные и проверенные действия.

## Исходное состояние

- Приложение - Job Platform из варианта 2 курса: семь микросервисов на Node.js, Express и TypeORM.
- ЛР3 уже содержит Dockerfile каждого сервиса, общий Docker Compose, семь отдельных PostgreSQL и внутреннюю Docker-сеть.
- ДЗ5 добавляет RabbitMQ, но ЛР4 является прямым продолжением контейнеризированной ЛР3, поэтому основой ЛР4 выбран `labs/lab3` без добавления не требуемых ТЗ компонентов.
- ДЗ6 уже имело GitHub Actions workflow, однако контрольный запуск 27.09.2026 выявил нерабочую SSH-аутентификацию: сервер был доступен, но secret `SSH_PRIVATE_KEY` отсутствовал, а сохраненный `SSH_PASSWORD` не подошел.

## Требования заданий

### ЛР4

1. Подготовить удаленный сервер и установить необходимые зависимости.
2. Развернуть приложение на удаленном сервере.
3. Настроить Nginx в режиме обратного прокси для внешнего доступа.
4. Подготовить отчет.

### ДЗ6

1. Настроить автоматическое развертывание приложения на удаленный сервер.
2. Использовать обновление кода в выбранной ветке как trigger.
3. Реализовать процесс средствами GitHub Actions.
4. Подготовить отчет.

## Проверка удаленного сервера

Проверка выполнена до внесения изменений:

- ОС: Ubuntu 20.04.6 LTS;
- оперативная память: 1,9 ГБ;
- swap: 2,2 ГБ;
- свободное место: около 456 ГБ;
- Docker: 26.1.3;
- Docker Compose до начала работы отсутствовал;
- Nginx: 1.18.0;
- порты 80 и 443 уже используются существующим Nginx;
- на сервере работают сторонние VPN/x-ui-компоненты, которые нельзя останавливать или заменять;
- средняя нагрузка во время проверки была ниже 0,2.

Из-за ограниченного объема памяти сборка Docker-образов должна выполняться последовательно (`COMPOSE_PARALLEL_LIMIT=1`). Существующая конфигурация Nginx сохраняется, а Job Platform подключается отдельным URL-префиксом.

## Ход реализации

### ЛР4: локальная конфигурация

- Создана папка `labs/lab4` на основе ЛР3.
- В Compose добавлено имя проекта `job-platform-lab4`.
- JWT, service token и пароль БД берутся из `.env`, а не хранятся в Compose.
- Backend-порты привязаны к `127.0.0.1`; порты PostgreSQL не публикуются.
- `deploy/setup-server.sh` подготавливает зависимости.
- `deploy/deploy.sh` собирает образы по одному, запускает стек, применяет миграции и делает smoke-тест.
- `docker compose config --quiet` успешен.

### ЛР4: удаленный сервер

- Установлен Docker Compose v2.34.0; уже работавшие Docker и Nginx не переустанавливались.
- Проект размещён в `/opt/job-platform-lab4/app`.
- `.env` создан на сервере со случайными значениями и правами `600`.
- Семь backend-образов успешно собраны последовательно.
- Запущены 7 backend-сервисов и 7 PostgreSQL; все базы прошли healthcheck.
- Все 7 TypeORM-миграций завершились успешно.
- Nginx подключает приложение по `/job-platform`; перед reload выполнен успешный `nginx -t`.
- Внешние запросы `/job-platform/`, `/industries`, `/vacancies` и Swagger возвращают HTTP 200.
- Порты 3001-3007 слушаются только на `127.0.0.1`; PostgreSQL-порты на host отсутствуют.
